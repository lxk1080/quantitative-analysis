# 量化选股工具需求文档

## 1. 项目目标

本项目是一个运行在本机的 A 股量化选股工具。它持续维护一套可靠、可追溯的非 ST 股票行情数据库，并根据用户配置的量价与技术指标条件，在盘中或盘后筛选符合条件的股票。

项目首先解决两个问题：

1. 用户无需每次筛选时临时从外部拉取并清洗全市场数据；历史日线、指标和同步状态会被统一维护。
2. 盘中实时价格与盘后前复权日线价格使用同一比较尺度，避免将未复权实时价直接与前复权均线比较而产生错误信号。

本工具只提供数据整理、条件筛选和结果展示，不提供自动交易、投资建议、收益承诺或价格预测。

## 2. 使用者与使用场景

使用者是需要依据自定义技术条件观察 A 股股票的个人研究者。

### 2.1 盘后筛选

用户点击“盘后筛选”。系统以已确认的当日收盘行情为当前价格，基于最近 70 个已完成交易日的前复权日线和指标执行筛选，例如：

- 收盘价站上 MA60；
- MA5 上穿 MA10；
- 成交量高于近 5 日平均成交量；
- DKX 上穿其信号线；
- 多个条件组合过滤。

### 2.2 盘中筛选

用户点击“获取实时行情”后，再点击“盘中筛选”。系统保留已确认日线不变，将实时价转换为前复权等价价格，替代当日价格参与条件判断；成交量等盘中字段使用当前实时快照。

盘中结果是一个带时间戳的行情快照结果，不会覆盖当日尚未收盘的正式日线记录。

### 2.3 数据维护

用户可在界面中查看数据新鲜度、覆盖股票数、失败数和异常数，并通过“刷新历史数据”或“更新盘后数据”发起后台同步任务。

## 3. 功能需求

### 3.1 股票范围

- 默认范围为沪深京普通 A 股。
- 证券简称含 `ST` 或 `*ST` 的证券不得进入股票池、历史日线表、实时筛选结果或任何指标计算。
- 股票池在每次全市场同步前刷新。已入库股票后来被实施风险警示时，其现有日线保留用于审计，但状态更新为不可筛选，后续筛选必须排除。
- 基金、ETF、LOF、REITs、可转债、指数、B 股及无法明确识别为普通 A 股的证券不纳入股票池。

### 3.2 日线数据与保留规则

- 每只可筛选股票在数据库中最多保留最近 **70 个已完成交易日** 的数据。
- 日线至少包括交易日、前复权开盘/最高/最低/收盘价、成交量、成交额和换手率（来源可用时）。
- 首次运行或缺少数据时，系统自动补采。为计算被保留 70 天内每一天的 MA60，首次同步需临时取得至少 129 个交易日；实现上建议请求 140 个交易日，以留出边界余量。
- 每日同步在完整写入、校验与指标计算成功后，才删除第 71 个交易日前的数据。任何失败不得导致已有有效数据被清空。
- 新股或停牌导致历史不足 70 日时，如实保存已获得的数据；MA60 等所需样本不足的指标为不可用，不得以 0、插值或猜测值替代。

### 3.3 价格与指标

- 历史 OHLC 价格统一使用前复权价格。
- 成交量、成交额是原始市场成交统计，不做价格复权。
- 系统至少计算并保存 MA5、MA10、MA60、DKX；DKX 信号线（默认 MADKX10）作为后续筛选扩展项一并预留。
- 指标由统一指标引擎生成。页面、API 和筛选规则不得各自重新实现公式。
- 所有指标必须记录其依赖的交易日、计算版本和数据版本，以支持重算与审计。

### 3.4 实时行情与前复权一致性

- 交易时段内，价格条件使用最新实时价；收盘后使用已确认的当日收盘价。
- 外部实时行情若为未复权现价，系统需依据最近一个已完成交易日的原始收盘价和前复权收盘价计算复权因子：`qfq_factor = qfq_close / raw_close`，再计算 `qfq_realtime_price = raw_realtime_price × qfq_factor`。
- 遇到除权除息日、复权因子缺失、锚点数据不一致或来源无法确认时，盘中前复权等价价应标记为不可用；依赖价格比较的规则不得对该股票给出“符合”。
- 实时快照和正式日线分表保存。实时价不得在收盘确认前写入 `daily_bars`。

### 3.5 选股规则与结果

- 支持由多个条件组成的“全部满足（AND）”选股规则；后续可扩展“任一满足（OR）”、分组与自定义表达式。
- 首期规则类型包含价格与 MA 的位置/穿越关系、均线关系、成交量/均量关系、DKX 与信号线关系、连续 N 日条件。
- 每次筛选产生可追溯的结果快照，保存规则版本、运行模式（盘中/盘后）、使用的行情时间、股票数量、命中股票及各条件的命中明细。
- 数据过期、指标不足、价格转换失败或数据质量未通过时，股票被标为“不参与本次筛选”，并显示原因；不得静默当作不符合。

### 3.6 可视化界面

界面至少提供：

- 数据概览：最近同步时间、股票池数量、日线覆盖度、实时行情时间、异常数量；
- 数据管理：刷新历史数据、更新盘后数据、获取实时行情、查看后台任务进度和日志；
- 选股器：创建/编辑条件、选择盘中或盘后模式、发起筛选；
- 筛选结果：股票代码、名称、当前价、关键指标、命中条件、数据时间和质量状态；
- 个股详情：最近 70 个交易日 K 线、成交量、MA5/10/60、DKX 和该股票数据状态。

## 4. 数据质量与非功能需求

### 4.1 正确性与可追溯性

- 数据源、请求时间、原始/标准化状态、校验结果和错误信息必须记录。
- 同一 `(stock_code, trade_date)` 只能有一份当前有效日线记录；重复同步使用幂等更新。
- 关键写入使用数据库事务；保留期清理必须与成功同步在同一事务边界内完成。
- 对收盘价、复权状态、交易日期和股票范围进行校验。来源冲突或异常跳变必须进入待复核状态，而不是静默选择数值。
- 数据库在每日成功盘后同步后自动生成备份；备份保留策略可配置。

### 4.2 性能

- 约 5,000 只股票、70 个交易日约为 35 万条日线记录，单机 SQLite 可满足首期需求。
- 全市场同步为后台任务，不阻塞网页请求；界面可轮询显示进度。
- 常用筛选查询应在普通电脑上于数秒内完成，依赖 `(trade_date, stock_code)`、`stock_code` 和指标日期等索引。

### 4.3 可维护性与扩展性

- Next.js/TypeScript 负责产品界面、业务交互、API 与任务编排；不承载行情同步、复权或指标公式。
- 数据源通过 Provider 接口隔离，任何供应商的字段变化不应影响数据库与筛选规则。
- Python Quant Worker 从首期起承担行情同步、前复权处理、指标计算和全市场筛选；后续在同一计算层扩展回测、因子研究、优化和机器学习。它与 Node.js 共享数据库契约和任务表，而不重写界面。
- 数据库访问层采用 Drizzle ORM，并保留执行经过测试的原生 SQL 的能力，用于批量 UPSERT、窗口查询和维护任务。

## 5. 范围边界

首期不包含：

- 自动下单、券商交易连接；
- 预测模型、荐股结论、仓位建议；
- 分钟线或逐笔历史库；
- 多用户权限、云端部署和跨设备同步；
- 全量长期历史日线存储。

## 6. 首期验收标准

1. 可以自动建立非 ST 股票池，并排除 ST、*ST 与非普通 A 股证券。
2. 任一股票的日线数据始终不超过最近 70 个已完成交易日；首次缺失时可自动补齐。
3. 日线价格明确为前复权，MA5、MA10、MA60、DKX 计算结果可复算验证。
4. 盘中实时价不会写入未确认日线，且与前复权指标比较前经过转换或被明确标记为不可用。
5. 同步失败不会删除既有有效日线；同步、校验、保留清理和备份均有日志。
6. 用户可从界面发起盘中与盘后筛选，并查看每个结果使用的数据时间与命中依据。
